Prediction Method · The Rubric

How each model turns a market into a number: the sport-tiered criteria rubric

Every model on the panel scores the same market against the same factors, in the same order, on the same scale. That is what makes dozens of different models comparable: their confidence is not a gut feeling, it is a weighted average of explicit judgments. The twelve below are the universal core that every sport shares, drawn from A structured set of factors; tennis, baseball and football each add their own tier on top. Each factor is scored from 0 to 1 toward the model's own pick, where 0.5 means unknown and is dropped so it cannot dilute the signal. Factors are weighted by how reliably they predict, so a market-edge read counts far more than a weather note.

Design Rationale · 03

Memory architecture: vector retrieval and a marker ledger

Similarity memory and durable event history answer different questions. Storage dimensions, table inventories, and private deployment details are omitted.

Vector MemoryWhat it remembers

Operator trades, unusual plays, per-model accuracy, chat Q&A, error-to-fix pairs, game outcomes, news sentiment, model-meeting insights, market text, and lifecycle evidence. Each table answers one recall question well.

Vector similarity indexingWhy this index

High-dimension embeddings exceed the standard HNSW limit, so vectors are indexed as half-precision with cosine ops. Approximate search trades recall, latency, and storage; validate the choice on representative queries.

Marker LedgerHow history survives

Every reset, graft, sweep and bundle writes one typed, additive row. Vectors answer "what is similar"; the marker ledger answers "what happened to this seat, and when." Nothing is ever mutated, so a reset is a time floor rather than a deletion.

Redis LayerWhy chosen

In-memory cache, cross-restart alert dedup, and signal pub/sub. Notifications survive restarts without double-firing, and hot data never touches the database.

Backup & ReplicationWhy chosen

Git history alone does not back up a database, secrets or runtime state, so backup and restore are documented separately and audited by a read-only readiness check. Recovery is a written runbook, not an assumption.

Retrieval DisciplineWhy chosen

Recall is filtered by distance thresholds and hit counters, cached answers are reused when close enough, and repeated model discussions are deduplicated before they waste tokens.

Deep Dive · 01 · Security

Defense in depth: twelve layers, each closing a specific threat

PolyMind is a financial system that acts with real money, so it is engineered the way security people expect: no single control is trusted to be perfect, and the layers are arranged so a bypass of one still lands on the next. Every layer below was validated by an independent AI red-team pass. Mechanisms are described in general terms; no secrets, endpoints, or bypass details are exposed.

Network perimeter

Every sensitive service (database, cache, metrics, admin dashboards) binds to loopback only by default. LAN exposure is opt-in and is deliberately coupled to also setting an access token. The stack refuses to start without its required passwords set.

Threat: LAN-reachable databases and admin control surfaces

Container hardening

Slim base image, exact-pinned dependencies, and a dedicated non-root user that owns the app and data directories. A compromised process runs unprivileged, and the runtime scanner confirms the non-root posture actually holds in the deployed image.

Threat: post-exploitation blast radius

Secrets handling

Secrets, keys, and runtime data are excluded from version control. The exchange signing key is loaded from a mounted file and never baked into the image, and requests are signed with RSA-PSS over a timestamped payload. Credentials are checked at startup against their packaged defaults.

Threat: credential commit, key-in-image, signing-key exposure

Prompt-injection defense

Every piece of external text (market titles, scraped news, API payloads, chat, retrieved memory) passes a sanitizer before any model sees it: forged boundary tags are stripped, a family of instruction-override patterns is redacted, secret-shaped strings are scrubbed, control characters and code fences are neutralized, and sanitized content is wrapped in explicit untrusted-data blocks that cannot outrank system instructions.

Threat: direct and stored/RAG prompt injection, delimiter escape, secret echo

Egress secret scrubbing

The design calls for constrained inputs, protected secrets, and reviewed publication boundaries. These mechanisms reduce risk; they do not establish complete prevention.

Threat: secret leakage through error text

API authorization

Three concentric checks: middleware requiring a constant-time-compared token for any non-local caller, a per-route dependency on every stateful endpoint, and a separate confirmation-header nonce on top of auth for destructive routes. Plus per-address rate limiting, a strict Content-Security-Policy, anti-clickjacking and no-sniff headers, same-origin CORS, and HMAC-verified webhooks with a replay window. The dependency is now applied at the mount, not only per route: a September 2026 whole-tree review found one mounted router attached without it, closed the gap the same day, and pinned it with a source-contract test and a behavioral 403 test, so every mounted surface sits behind the same loopback-or-token check by construction.

Threat: unauthenticated control, CSRF, clickjacking, XSS, webhook spoofing, flood DoS

Command-channel authorization

The chat command center authorizes at the user-identity level and fails closed: with no operator identity configured, all commands are refused. Authorization follows the person, not the room, so a leaked group chat cannot issue commands. Uploads are content-type and size validated and stored under generated filenames.

Threat: impersonation and unauthorized control of the trading bot

Autonomous security scanner

Scheduling, health monitoring, and release verification are distinct responsibilities. Their private operational settings are not included in this conceptual view.

Threat: config drift and exposure regressions over time

Data-integrity & anti-fake-win

The market API, not any model, is the source of truth for outcomes. A QA loop re-checks every recently resolved trade against the API; if a win cannot be verified, the trade is reverted, the P&L is unwound, and a fix record is written. Independent scans catch wins on unresolved markets, negative stakes, and orphaned positions.

Threat: models fabricating outcomes and inflating results

Public boundary

The public dashboard renders only an explicit allow-list of fields, so a new database column is private by default. The backend URL is validated against an allow-list to contain server-side request forgery, and the proxy exposes only a handful of named read-only paths, all marked no-index.

Threat: sensitive-field leakage and SSRF on the public surface

Supply-chain guards

Every Python dependency is exact-pinned, the pin set is reviewed against published advisories, and the base image is pinned by digest and runs as a dedicated non-root user. Automated dependency updates arrive weekly for Python and the front-end and monthly for the CI actions, grouped by patch level, with automated bumps withheld where a published release is known to be compromised. The public front-end keeps a committed lockfile and a prebuild scanner encoding known compromised-package indicators that fails the build on any poisoned or drifted dependency, and a secrets scanner guards commits. This mirrors the standard-library-only discipline of the public Showcase repository, which declares no dependencies at all.

Threat: dependency-confusion and publish-hijack compromise

Financial kill switches

An operator-set emergency stop halts scheduled activity; blocked leagues and banned market types are rejected before analysis; bankroll, stake-tier, and leverage invariants are enforced in the database and flagged critical on violation; and any browser-driven order is capped at a hard ceiling.

Threat: runaway autonomous trading and oversized orders

An independent red-team pass (network exposure, dependency CVEs, prompt injection, cross-site scripting, log hygiene, path traversal) drove most of these controls, and the audit trail of what was tested, fixed, and verified is itself part of the repository. The discipline is periodic, not one-off: the September 2026 whole-tree review ran five independent read-only reviewers over the entire tree and its history, triaged thirty-one findings and nine synthesized attack chains, confirmed that all but one were already-hardened controls, findings outside the application’s own code, or operator-side actions no code change can perform, and fixed the one real code-level gap with a regression test in the same change. A fix registry ties each historical incident to the exact test that now keeps it closed, and labels the few that are enforced by written procedure rather than by code, because a materially weaker guarantee deserves its own name.

Deep Dive · 03 · Self-Learning

The closed loop, traced end to end

Here is the honest version, because a technical audience respects precision. PolyMind does not fine-tune the underlying models. It runs a genuine closed feedback loop where real market outcomes rewire which models it trusts and what context it feeds them. Ground truth comes from an external market API, never from a model grading itself, and that is the hard part done right. Since July 2026 the loop has grown a second layer, a self-learning substrate that measures each model's settled record, refuses to publish a rate without its null, and mints skills only from evidence; the September 2026 review of that layer is summarized below, with what it measured, what the system refuses to claim, and what changed when a check found a flaw.

Resolve on ground truth

A watchdog closes out every open position against the market API. A model-based resolver exists only as an advisory suggestion; it can never close a trade or move money on its own.

Stamp the prediction

Each resolved trade stamps its prediction as correct or not, with a timestamp. That single stamp is the linchpin of the entire loop, and it fans out to four separate memory tables.

Filter the junk

Before any statistic is computed, a hard-gate excludes three classes of misleading rows: legacy categories, stale records logged long after the event, and after-the-fact rows where a model backed a side it had rated nearly impossible.

Score calibration and Brier

Per model and per sport, the system computes textbook Brier scores and a ten-bucket calibration ladder comparing claimed confidence against realized win rate. The math is bounds-checked.

Rebuild the weights

Scheduling, health monitoring, and release verification are distinct responsibilities. Their private operational settings are not included in this conceptual view.

Govern the roster

Those weights gate membership: dead or degraded endpoints are forced to zero and dropped from the active roster, probation triggers on a policy-defined review trigger, and a policy-defined review trigger ejects a seat and promotes one from the bench.

Feed memory into the next prompt

On every resolved trade the system embeds the game context, the per-model result, and the news outcome. Before the next similar market, it retrieves which model was right in comparable conditions and injects that track record, as untrusted data, into the prompt.

Coach the strugglers

A model on probation gets a personalized scaffold prepended to its next prompt: its own recent wins, its league record, and a calibration target, with explicit instructions to incorporate the evidence rather than copy the current leader.

Guard against degenerate learning

During independent-reasoning epochs the copy-the-winner memory is deliberately suppressed so seats reason fresh, proposed threshold changes queue for human review, and epoch resets cleanly scope history without deleting it.

Azure AI Search

Exactly what the search service does

AI Search is the research memory and grounding engine. It is not a keyword box; it is a hybrid vector store with a reranker, so "have we researched something like this, and what was true" returns cited, ranked, relevance-scored evidence the models can ground on.

Vector searchHNSW

Approximate-nearest-neighbor over embeddings, the same vectors the pgvector brain uses, for semantic recall of past research.

Hybrid retrievalKeyword + vector

Fuses BM25 keyword scoring with vector similarity, so exact terms and semantic meaning both count, then reciprocal-rank-fuses the results.

Semantic rankerL2 reranking

A second-stage reranker reorders the top results by deep relevance and returns captions and answers, sharpening what the model grounds on.

Integrated vectorizationSkillsets + indexers

Indexers pull new research, chunk it, and call the embedding model automatically, so the index stays current without a custom pipeline.

Scoring profilesFreshness bias

Boosts recent and high-provenance sources, so a fresh injury report outranks a stale note on the same topic.

Security trimmingPrivate + filtered

Runs behind a Private Endpoint, with document-level filters so a query only ever sees what it is allowed to.

What "quantum" means here

Exactly what it means in the codebase: classical, labeled, checkable arithmetic (a Beta posterior, a Wilson interval, Shannon entropy over a bounded observation), never a fabricated computation claim. No quantum hardware, no qubits, no speed-up. The repository's own methods document says so in those words, and a test fails the build if a label claims more than the code does.

The three states that never collapse

NOT_MEASURED the read failed or was not attempted; counts are null. MEASURED_NONE the read succeeded and returned zero rows. MEASURED k of N, every count an integer. A fourth, NOT_AVAILABLE, means the module that would answer is absent from this process.

Earned versus unearned

UNEARNED is a first-class verdict: a rate without its null, a calibration nobody fitted on this row, a skill transferred rather than settled. The word appears on the page whenever it appears in the system, because a hidden default is the most reassuring failure there is.
